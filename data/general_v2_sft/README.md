# Scrabble generalization SFT corpus v2

This corpus trains general immediate-score Scrabble play. It contains no
official benchmark position and was not constructed from model responses on
the official benchmark.

## Provenance and split policy

- Self-play seeds: 200000–200255 and 300000–300127.
- Source games: 383 complete games generated by the exact project solver.
- Split unit: a complete game; positions from one game never cross splits.
- Training: 306 games, 3,366 positions, 5,058 conversations.
- Validation: 37 games, 407 positions/conversations.
- Frozen generated test: 40 games, 440 positions/conversations.
- Checkpoint selection: 55 validation positions, exactly five at each ply 4–14.
- Training augmentation: one deterministic identity or transpose view per
  position. Transpose preserves the premium layout and word direction.
- Recovery training: 1,692 training positions also include one invalid move,
  the exact validator rejection, and a corrected optimal response.

All 100 official benchmark board+rack hashes were inserted into the deduplication
set before generated positions were accepted. `source_audit.json` additionally
revalidates every canonical move and checks official overlap, cross-split
board+rack overlap, cross-split game overlap, duplicate IDs, and selection-set
membership. Every audit count is zero and `passed` is true.

## Reproduction

```bash
python scripts/generate_training_data.py \
  --games 256 --workers 4 --seed-start 200000 --output-dir data/general_v2

# The second shard uses 128 games beginning at seed 300000.
python scripts/merge_general_position_shards.py \
  data/general_v2 data/general_v2_remote --output-dir data/general_v2_merged
python scripts/audit_general_dataset.py data/general_v2_merged
python scripts/build_general_training_data.py \
  --input-dir data/general_v2_merged \
  --output-dir data/general_v2_sft --recovery-rate 0.5
```

`manifest.json` contains record counts, recovery-error categories, byte sizes,
and SHA-256 hashes. The JSONL conversations use the same system/user prompt and
validator retry feedback as the benchmark runner. Assistant loss is applied
only to the concise solver-derived reasoning and final `play_move` JSON.
